# 上海大学科学家精神数字展馆 V1 设计规格

日期：2026-08-15  
状态：待用户书面复核  
目标：当天完成可公开访问、可通过 GitHub 协作维护的响应式首版

## 1. 项目目标

网站定位为“红色文化 × 科技档案 × 现代博物馆”的上海大学科学家精神数字展馆。它不是学院新闻门户，也不是人物百科，而是通过“人 → 事 → 精神 → 时代 → 传承”的叙事，让公众在浏览人物故事的过程中理解科技报国、自立自强、求真务实和薪火相传。

首要受众为比赛评委、学校领导和教师，同时保证中小学生、大学生及普通公众能够看懂并愿意继续浏览。PC 端承担答辩与大屏展示，移动端承担扫码传播；两端内容完整一致，移动端适当减少非必要动效。

## 2. V1 范围

### 2.1 当天上线内容

- 响应式数字序厅首页。
- 钱伟长、李三立、黄宏嘉三位核心人物专题展。
- 孙晋良、周邦新、杨雄里、谢少荣、岳晓冬等人物的群像卡片。
- 汇总人物、科研和时代节点的“岁月长河”时间轴。
- 以科技报国、自立自强、勇攀高峰、求真务实、甘为人梯、薪火相传为核心的“精神谱系”。
- 展示进支部、进校园、进社区、进军营等成果的“精神足迹”。
- 影音档案入口；无可公开资源时使用明确的“持续整理中”状态，不伪造视频或链接。
- 轻量人物关系图，用可访问的 HTML/SVG 或轻量图形方案表达人物、领域和精神关键词的联系。
- 关于项目、团队信息和联系方式。
- 内容数据与页面组件分离，使用 Markdown、JSON 或 TypeScript 数据文件维护。
- 基础 SEO、分享信息、404 页面、无障碍和响应式适配。

### 2.2 V1 明确不做

- 登录、权限和可视化内容管理后台。
- 小程序及统一后端 API。
- 数据库驱动的完整知识图谱系统。
- 复杂 GIS 活动地图；V1 使用地点卡片或轻量示意图。
- WebGL、3D 人物、大规模粒子、自动播放音频或不可跳过的开场动画。
- 未经核实的人物信息、统计数字、档案来源或外部媒体链接。

### 2.3 V2 方向

V2 再建设内容管理后台、权限体系、数据库、网站与小程序共享 API、可扩展知识图谱和精确活动地图。V1 的内容模型应为后续迁移保留稳定字段，但不提前实现上述基础设施。

## 3. 视觉系统

核心气质为庄重、克制、历史感、青年化、数字化和博物馆感。页面以米白 `#F3EFE7`、墨黑 `#171717` 和旧纸色 `#D5C5A6` 为大面积背景；深朱红 `#8F1D22` 与中国红 `#C52A2F` 用于品牌和精神强调；铜金 `#A68452` 仅用于数字、细线和档案标记。

历史照片统一采用黑白、低饱和、轻颗粒和高对比处理；当代实践照片保留彩色，以“历史是沉静的，精神在今天重新拥有颜色”建立视觉对照。避免满屏红色、亮金、红旗与光芒堆叠、过度科技蓝和满屏发光粒子。

动效比例为“70% 静态高级感 + 30% 克制动效”。V1 使用首屏渐入、滚动显现、人物卡片轻微放大与局部复色、时间轴生长和数字递增。尊重系统的减少动态效果设置；移动端简化耗性能的动画。

## 4. 信息架构

主导航控制为：首页、前辈群像、岁月长河、精神谱系、科学家图谱、精神足迹、影音档案；“关于项目”放入导航辅助位置或页脚。

### 4.1 首页

首页是数字序厅，依次完成以下叙事：

1. 项目主题与一句话价值主张。
2. 三位核心人物入口。
3. “人 → 事 → 精神 → 时代 → 传承”的展馆导览。
4. 岁月长河精选节点。
5. 六类精神主题。
6. 轻量人物关系图入口。
7. 宣讲成果统计与代表性活动。
8. 影音内容和项目说明。

首页不采用新闻列表或密集卡片门户结构。

### 4.2 核心人物专题

三位核心人物统一采用六段式结构：

1. 人物序章：大幅照片、姓名、生卒年份、身份和一句话概括。
2. 生平轨迹：求学、科研、任职、重大事件与荣誉。
3. 科研征途：按“问题 → 行动 → 意义”叙述关键成果。
4. 档案珍藏：照片、手稿、论文或资料说明；资源不足时不展示空展柜。
5. 精神印记：每个关键词必须关联具体故事。
6. 薪火相传：连接当代宣讲、青年感悟和下一位人物。

### 4.3 群像、时间轴与精神谱系

群像页面提供人物卡片和轻量筛选。V1 优先支持学科领域与精神关键词；仅在数据完整时开放年代或科研方向筛选。时间轴复用统一事件数据。精神谱系从关键词反查人物与故事，不重复维护内容。

### 4.4 精神足迹与影音档案

活动记录包含名称、时间、地点、类型、人物、图片、人数和简介。统计数字必须来自已核实材料。影音条目包含标题、封面、类型、简介、关联人物和可公开访问地址；没有合法地址的内容标记为整理中。

## 5. 内容与数据设计

V1 使用本地结构化内容，不将正文散落硬编码在组件里。建议数据实体包括：

- `scientists`：人物基本信息、图片、领域、简介和精神关键词。
- `stories`：人物故事、问题、行动、意义和引用来源。
- `events`：年份、标题、说明、人物、成果和时代背景。
- `archives`：档案名称、类型、年份、图片、来源和关联对象。
- `activities`：宣讲活动、时间、地点、类型、照片和覆盖人数。
- `media`：影音标题、封面、地址、类型和关联人物。
- `spiritThemes`：精神主题及其关联故事。

图片和内容记录采用稳定 ID 关联。字段允许缺失时，组件应隐藏对应区域或显示诚实的整理状态，不渲染 `undefined`、空白弹窗或虚构占位内容。

## 6. 技术结构

首版采用单一前端应用和静态构建，避免当天上线依赖数据库或后端服务。模块边界如下：

- 页面路由：组织各栏目和人物专题 URL。
- 展馆组件：首屏、人物卡、章节、时间轴、档案查看器、统计和关系图。
- 内容层：集中导出结构化数据并校验必填字段。
- 动效层：只负责进入视野、计数和时间轴动画，不承载业务内容。
- 媒体层：统一图片比例、懒加载、替代文本和失败回退。
- 部署层：生成静态产物，可先托管到静态站点，正式服务器获批后迁移至 Nginx。

具体框架、依赖和目录结构在实施计划中确定。选择标准是当天可交付、团队容易接手、静态托管方便和后续能迁移到 API 数据源。

## 7. 异常与降级

- 图片加载失败时显示与版式一致的替代区域和人物姓名。
- 外部视频不可访问时不自动跳转，显示说明和返回入口。
- 关系图在小屏或脚本失败时降级为可点击的关系列表。
- 动效不可用或用户选择减少动态效果时，内容仍完整可见。
- 筛选无结果时提供清晰空状态和重置操作。
- 未找到页面进入站内 404，并可返回首页或人物群像。
- 所有内容缺失、错误和链接异常均以不阻断主要阅读为原则处理。

## 8. 多人协作与 GitHub

- 默认分支为 `main`，保持可部署状态。
- 功能或内容修改使用短期分支，通过 Pull Request 合并。
- 页面开发、数据整理、图片处理和内容校对可独立分工。
- 人物事实、统计数字和档案来源的修改必须经过内容复核。
- 图片、视频不直接无节制提交到 Git；大文件采用外部对象存储、视频平台或后续约定的大文件方案。
- 项目提供 README、贡献指南、内容字段说明、素材命名规范和部署手册。
- `.superpowers/`、构建产物、缓存、环境变量和本地临时文件不进入仓库。

## 9. 部署策略

当天首版以静态部署为目标。若 GitHub 仓库和可用静态托管账号已准备好，则完成公开 URL；否则至少生成经本地验证的生产构建和完整部署步骤，待账号或权限到位后执行发布。

正式服务器阶段采用域名、HTTPS、Nginx 静态托管、压缩与缓存、访问日志和定期备份。V1 不需要数据库服务器。未来增加后台时，再单独评估 API、数据库、对象存储、鉴权和备份配置。

## 10. 验收标准

- 首页及所有 V1 栏目可访问，无死链和未完成占位文字。
- 三位核心人物拥有完整、连续且可读的专题叙事。
- PC 与主流手机宽度下无横向溢出、遮挡、截断或无法操作的元素。
- 键盘可访问主要导航与交互；图片具有合理替代文本；颜色对比可读。
- 页面在禁用动画和关系图降级时仍能完成全部核心阅读任务。
- 内容数据通过结构检查，人物、事件和精神主题的关联均指向有效 ID。
- 生产构建成功；静态资源路径在目标托管环境下正确。
- README、协作规范和部署手册足以让新成员完成本地启动、内容修改、检查和提交。

## 11. 交付阶段

1. 冻结本规格并编写实施计划。
2. 初始化工程、质量工具和 Git 协作文件。
3. 建立内容模型并录入首批人物与项目数据。
4. 完成首页、通用组件和核心人物模板。
5. 完成群像、时间轴、精神谱系、关系图、足迹和影音栏目。
6. 完成响应式、动效降级、可访问性和内容校对。
7. 执行生产构建与跨端验收。
8. 推送 GitHub，并在具备账号权限时完成首版发布。

## 12. 已推迟事项

以下项目不属于今天上线承诺：可视化管理后台、小程序、统一后端 API、数据库、完整可编辑知识图谱、精确地图系统、账号权限、在线投稿和自动化内容审核。它们必须在 V1 稳定上线后另立规格与实施计划。
